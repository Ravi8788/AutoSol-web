# AUTOSOL TECHNOLOGIES — Website Design & Build Brief
### Enhanced Edition — UI, Design System & Color Focus

> **What's new in this version:** a complete design-token system (color, type, spacing, elevation, motion) with exact values instead of general direction; explicit color-usage ratios and a section-by-section color map so the dark/light rhythm is deliberate, not arbitrary; component-level UI specs (buttons, cards, badges, forms) with defined states; and light-section tokens to complement the dark palette that was already defined. All original brand facts, copy, founders, projects and content rules are preserved unchanged.

---

## 0. PROJECT BRIEF

**Company:** AutoSol Technologies
**Tagline:** BUILD. AUTOMATE. GROW.
**Positioning:** AI • Software • Automation • Data • Growth • IoT

This is **not** a generic IT-services template. It is a premium, product-focused technology startup website that communicates AutoSol builds intelligent digital systems — AI, software, automation, data, SaaS, IoT, cloud, integrations, digital growth, and technology consulting — for real businesses.

**Primary goals:** brand building, client enquiries, showcasing services/projects/products-in-progress, technical capability, founders/team, training programs, and a premium startup identity.

**Hard content rule (applies to every section below):** never fabricate clients, revenue, users, awards, partners, reviews, certifications, statistics, funding, or history. Where real data isn't supplied, use a visible editable placeholder (e.g. `[PROJECT IMAGE]`, `[FOUNDER PHOTO]`, `[CLIENT REVIEW]`) — never invent a number to fill the gap.

```
Business Problem → Data → AI → Automation → Software → Business Outcome
```

**Feel:** modern AI startup + product company + engineering studio + digital innovation lab.
**Reference quality bar (inspiration only — never copy layout, text, or identity):** Vercel, Linear, Framer, Stripe.

**Use:** dark futuristic sections mixed with clean light sections, editorial typography, bento layouts, large type, subtle gradients, thin technical grid lines, network/node patterns, data-flow animation, dashboard mockups, soft glow, minimal glass surfaces, strong whitespace, premium case-study layouts.

**Usage rules — this is what keeps the site premium instead of "overloaded":**
1. **60 / 30 / 10 ratio per section:** ~60% neutral background/surface, ~30% text and structural elements (borders, icons, secondary text), ~10% brand accent color/gradient.
2. Gradient is reserved for: hero background wash, primary CTA hover glow, section divider lines, product/AI visuals, and at most one headline accent word per major section — **never** as a full-bleed fill behind body copy, and never on more than ~15% of a single viewport.
3. Text never sits directly on a multi-stop gradient without a solid or 80%+ opacity scrim behind it.
4. AI Purple is the rarest color in the palette — reserve it for AI/intelligence-specific moments (Products, AI & GenAI service, Product Philosophy). If a section isn't about AI specifically, lead with Electric Blue or Cyan instead.
5. Minimum contrast: body text ≥ 4.5:1 against its background; large headline text ≥ 3:1. Test Primary Text `#F8FAFC` on Deep Background `#07111F` (passes), and Secondary Text `#475569` on Light Background `#FFFFFF` (passes) before shipping.

### 2.2 Typography System

**Fonts:** Inter (primary — UI, body, nav, forms) · Manrope (display — large headlines only). Max two typefaces. An italic serif/accent face may appear on **one or two words per page at most**, as an editorial flourish — never paragraphs.

**Fluid type scale** (desktop → mobile via `clamp()`):

| Style | Size | Weight | Line-height | Tracking |
|---|---|---|---|---|
| Display / H1 | `clamp(2.5rem, 5vw, 5.5rem)` | 700–800 | 1.05 | −0.02em |
| H2 | `clamp(2rem, 3.5vw, 3rem)` | 700 | 1.1 | −0.01em |
| H3 | `clamp(1.5rem, 2.5vw, 2rem)` | 600 | 1.2 | normal |
| Body Large | 1.125rem | 400–500 | 1.6 | normal |
| Body | 1rem | 400 | 1.6 | normal |
| Caption / Eyebrow | 0.875rem | 600, uppercase | 1.4 | 0.08em |
| Button | 0.9375rem | 600 | 1 | 0.01em |

### 2.3 Spacing, Grid & Layout

- **Base unit:** 8pt scale — 4, 8, 12, 16, 24, 32, 48, 64, 96, 128, 160.
- **Section vertical padding:** 160px desktop / 96px tablet / 64px mobile.
- **Container:** max-width 1400px, gutter 24px desktop / 16px mobile.
- **Grid:** 12-column desktop, 8-column tablet, 4-column mobile (bento grids collapse to single/double column on mobile — never squeeze a 3-up grid into mobile width).

### 2.4 Elevation, Radius & Surfaces

**Radius scale:** 8px (badges, tags) · 12px (buttons, inputs) · 16px (cards) · 24px (feature panels, hero visual) · 999px (status pills).

**Shadow & glow tokens:**
- Light sections: soft ambient shadow, `0 8px 24px rgba(15,23,42,0.06)`, on hover `0 16px 40px rgba(15,23,42,0.10)`.
- Dark sections: colored glow instead of shadow, e.g. `0 0 40px rgba(37,99,235,0.25)` on hover for blue-accented elements, `rgba(124,58,237,0.25)` for AI/purple elements.

**Glass surface spec** (used sparingly — nav-on-scroll, hero product mockup frame, one or two key callouts; **not** every card): background `rgba(17,28,46,0.6)`, backdrop-blur 16–20px, 1px border `rgba(255,255,255,0.08)`.

### 2.5 Iconography & Imagery

- Line-style icons, 1.5–2px stroke, consistent corner radius on icon glyphs.
- No stock photography of generic offices/handshakes/robots. Imagery is either: real project/product screenshots, clearly-labeled mockups (see Projects section), or abstract system diagrams (nodes, lines, geometric shapes) built from the brand palette.
- Product/dashboard mockups use the dark palette with brand-accent data visualizations — treated as real interface design, not decorative illustration.

### 2.6 Core UI Components

**Buttons**
- *Primary:* solid Electric Blue fill (gradient shift to Cyan on hover), white text, radius 12px, padding 14×28px, arrow glyph that shifts 4px right on hover.
- *Secondary:* 1px border in current section's text color at 20% opacity, transparent fill, fills to a subtle tint on hover.
- *Ghost/text link:* no fill or border, underline or arrow-only hover motion.
- *States:* default → hover (150–200ms) → active (slight scale/darken) → focus-visible (2px outline, 2px offset, Electric Blue) → disabled (40% opacity, no pointer events).

**Cards** (service / project / product / founder / blog — one consistent base, varied content)
- Padding 24–32px, radius 16px, 1px border (Border token for the section's mode).
- Hover: `translateY(-4px)`, border shifts to brand accent, glow/shadow per 2.4. No scale-up inside grids (avoids layout shift/overlap).

**Status badges/pills** (radius 999px, small dot + label): `IN DEVELOPMENT` (amber), `PRODUCT VISION` (purple), `CAPSTONE / PROJECT` (slate), `CONCEPT / PROTOTYPE / HACKATHON PROJECT` (cyan outline). Never a green "live" badge on something that isn't live.

**Forms**
- Top-aligned labels, radius 12px inputs, 1px border, 2px Electric Blue focus ring.
- Error state: red border + inline helper text (never color alone — pair with an icon/text for accessibility).

### 2.7 Motion System

Motion is a major part of the site — but controlled, technical, premium. Never bouncy or cartoonish.

**Easing:** `cubic-bezier(0.16, 1, 0.3, 1)` for entrances (fast-out, gentle settle) · `cubic-bezier(0.65, 0, 0.35, 1)` for hover/state transitions.
**Durations:** micro-interactions 150–200ms · card hover 250ms · section scroll-reveal 500–700ms · page/route transition 300–400ms.
**Stagger:** 60–90ms between sibling elements (text lines, card grids).

**Hero choreography (kept from original spec, now with exact timing):**

| Time | Event |
|---|---|
| 0.00s | Background gradient + network lines appear |
| 0.15s | Logo fades in |
| 0.25s | Eyebrow text rises |
| 0.35s | Headline line 1 |
| 0.45s | Headline line 2 |
| 0.55s | Headline line 3 |
| 0.70s | Supporting description fades in |
| 0.85s | CTA buttons rise |
| 1.00s | Technology/dashboard visual animates in |
| 1.15s | Connected nodes activate |

**Also use:** scroll-triggered reveal (fade + translate), image parallax, gradient movement, glowing data nodes, magnetic CTA hover, horizontal marquee (tech stack), number/count-up **only where real data exists**, dashboard micro-interactions, cursor-responsive background glow on desktop only (not mobile), mobile menu slide-down.

**Accessibility:** full `prefers-reduced-motion` support — replace transforms with opacity-only fades, disable parallax and cursor-glow when reduced motion is requested.

------------------------------------------------------------

DO NOT create large unexplained empty areas.

- mobile sections with excessive vertical gaps

"premium whitespace" does NOT mean empty unused space.
